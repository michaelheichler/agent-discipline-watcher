# Caliber Learnings

Accumulated patterns and anti-patterns from development sessions.
Auto-managed by [caliber](https://github.com/caliber-ai-org/ai-setup) — do not edit manually.

- **[convention]** Keep machine-specific maintenance records outside the shared repository.
- **[convention]** Preserve unrelated settings and credentials during ADW maintenance.
- **[gotcha]** `claude plugin validate . --strict` exits 1 even on a clean tree. Two warnings cause this, and the user accepts both. The first is that `.claude-plugin/plugin.json` has no `version`, because ADW ships commit revisions instead of a version file. The second is that the root `CLAUDE.md` is not loaded as plugin context. Judge the run by its warning list rather than its exit code. Any third warning is a real failure.
- **[convention]** Every file in `commands/` needs a YAML frontmatter block with at least `description`, or the strict plugin validator fails. Quote `argument-hint` values, as in `argument-hint: "[--check]"`, because YAML reads an unquoted `[...]` as a list.
- **[pattern]** To reproduce the CI pylint run locally, run `uvx --python 3.11 --with pytest --from pylint pylint $(git ls-files '*.py')` from the repo root. Pylint exits nonzero on any single message. One leftover row drops the score to 9.95, and that fails CI.
- **[gotcha]** Piping pylint or pytest through `tail` hides their exit code. In the agent shell (zsh), `${PIPESTATUS[0]}` comes back empty. To get the real code, run the command without a pipe and then `echo $?`, or redirect its output to `/dev/null` or a file first.
- **[gotcha]** The full Python 3.11 suite (`cd hooks && uvx --python 3.11 --with pytest pytest . lib -q`) takes about 10 minutes, measured at 5663 tests in 594 s. That is right at the 600000 ms foreground Bash limit. Start it with `run_in_background: true` and read the task output file when it exits. For quick checks, run only the test files that cover your change.
- **[gotcha]** ADW's own gate blocks file writes made through inline interpreters, such as `python3 -c "open(...).write(...)"`, as `inline_interpreter_write`. Make every file change with the Edit or Write tool, even a trivial one like trimming a trailing newline.
- **[pattern]** To commit only part of the tree, stage it with pathspec excludes in one call, for example `git add -A -- . ':(exclude)CHANGELOG.md' ':(exclude).story/handovers'`. Then run `git commit` in the next call with no paths. The commit gate rejects path arguments on `git commit` but allows them on `git add`.
- **[pattern]** When other agents may edit the tree during a long QA run, record `shasum -a 256` of the files under test before the run and again after it. Matching hashes prove that the suite tested the tree you are about to commit.
- **[pattern]** To reproduce the CI pylint run locally, run `uvx --python 3.11 --with pytest --with pyyaml --from pylint pylint $(git ls-files '*.py')` from the repo root. Without `--with pytest`, every test file reports E0401 `Unable to import 'pytest'` and the score drops to 9.85. Pylint exits nonzero on any single message. One leftover row drops the score to 9.95, and that fails CI.
- **[correction]** When tests must change, delegate them to the test-writer agent yourself. Do not ask the user to open a test window with `adw-config tests allow`. The user rejected that handoff because the work belongs to the agent.
- **[gotcha]** The test-writer agent is registered as `agent-discipline-watcher:adw-test-writer`. The bare `subagent_type: "adw-test-writer"` fails. In a Claude Desktop session, an older account-plugin copy of ADW can hide the agent completely. Run `claude -p "Reply with only the exact subagent_type names ... that contain 'test-writer'" --max-turns 1` to check which names a CLI session can see. If the current session cannot see the agent, run the delegation through a headless `claude -p` session.
- **[gotcha]** `claude agents` refuses to run without a TTY. In the agent shell, use `claude agents --json`. Note that this lists running sessions, not subagent types.
- **[env]** The system `python3` has no pytest. Run tests with `cd hooks && uvx --python 3.13 --with pyyaml pytest -q <files>`.
- **[gotcha]** More than one ADW copy can run on one machine: the Claude Code plugin cache, `~/.adw/install`, and a claude.ai account plugin under `~/Library/Application Support/Claude/local-agent-mode-sessions/*/*/rpm/*`. A stale copy runs every hook a second time with old rules. Run `bin/adw-config status` to list every copy and its version before you debug odd blocks.
- **[gotcha]** Tests that call hook code without explicit roots read the real home folder. Machine state such as a stale ADW copy can then break them, and their rows land in `~/.adw/ledger/ledger.jsonl`. Pass `state_root` and `ledger_root` in the config, or use a seam such as `session_start.run(..., drift=lambda: "")`. For Claude reviewer paths that have no ledger root, monkeypatch `HOME` to `tmp_path`.
- **[pattern]** To prove that new tests can fail, write a throwaway pytest plugin in `/tmp` that rebinds names in memory, chosen by a `--mutant` option. Run it with `uvx --python 3.13 --with pyyaml pytest -q -o pythonpath=/tmp/<dir> -p <plugin> -p no:cacheprovider --mutant <name> <test file>`. Production files stay untouched.
- **[gotcha]** At commit time, the commit gate scans every staged file and blocks on prose and comment findings such as `prose_colon`, `passive_voice`, `what_docstring`, and `long_comment`. Each block writes a report to `~/.adw/reports/`. Read the newest report with `/bin/ls -t ~/.adw/reports/*.json | head -1`. Plain `ls -t` is aliased in the agent shell and fails with `invalid value for '--time'`.
- **[pattern]** Before you commit, check staged docs and code yourself. Run `scan_all` from `hooks/lib/scanner.py` with `payload_hook_config` and `resolve_outcome` from `hooks/lib/config.py` in a script outside the repo, invoked with `python3 -I`. Fix every row that resolves to `block` and restage it, so the commit gate does not stop the commit.
