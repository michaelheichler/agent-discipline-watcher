# Caliber Learnings

Accumulated patterns and anti-patterns from development sessions.
Auto-managed by [caliber](https://github.com/caliber-ai-org/ai-setup) — do not edit manually.

- **[gotcha]** ADW's own gate blocks file writes made through inline interpreters, such as `python3 -c "open(...).write(...)"`, as `inline_interpreter_write`. Make every file change with the Edit or Write tool, even a trivial one like trimming a trailing newline.
- **[pattern]** To commit only part of the tree, stage it with pathspec excludes in one call, for example `git add -A -- . ':(exclude)CHANGELOG.md' ':(exclude).story/handovers'`. Then run `git commit` in the next call with no paths. The commit gate rejects path arguments on `git commit` but allows them on `git add`.
- **[pattern]** When other agents may edit the tree during a long QA run, record `shasum -a 256` of the files under test before the run and again after it. Matching hashes prove that the suite tested the tree you are about to commit.
- **[pattern]** To reproduce the CI pylint run locally, run `uvx --python 3.11 --with pytest --with pyyaml --from pylint pylint $(git ls-files '*.py')` from the repo root. Without `--with pytest`, every test file reports E0401 `Unable to import 'pytest'` and the score drops to 9.85. Pylint exits nonzero on any single message. One leftover row drops the score to 9.95, and that fails CI.
- **[correction]** When tests must change, delegate them to the test-writer agent yourself. Do not ask the user to open a test window with `adw-config tests allow`. The user rejected that handoff because the work belongs to the agent.
- **[gotcha]** The test-writer agent is registered as `agent-discipline-watcher:adw-test-writer`. The bare `subagent_type: "adw-test-writer"` fails. In a Claude Desktop session, an older account-plugin copy of ADW can hide the agent completely. Run `claude -p "Reply with only the exact subagent_type names ... that contain 'test-writer'" --max-turns 1` to check which names a CLI session can see. If the current session cannot see the agent, run the delegation through a headless `claude -p` session.
- **[gotcha]** `claude agents` refuses to run without a TTY. In the agent shell, use `claude agents --json`. Note that this lists running sessions, not subagent types.
- **[env]** The system `python3` has no pytest. Run tests with `cd hooks && uvx --python 3.13 --with pyyaml pytest -q <files>`.
- **[gotcha]** More than one ADW copy can run on one machine: the Claude Code plugin cache, `~/.adw/install`, and a claude.ai account plugin under `~/Library/Application Support/Claude/local-agent-mode-sessions/*/*/rpm/*`. A stale copy runs every hook a second time with old rules. Run `bin/adw-config status` to list every copy and its version before you debug odd blocks.
- **[gotcha]** Tests that call hook code without explicit roots read the real home folder. Machine state such as a stale ADW copy can then break them, and their rows land in `~/.adw/ledger/ledger.jsonl`. Pass `state_root` and `ledger_root` in the config, or use a seam such as `session_start.run(..., drift=lambda: "")`. For Claude reviewer paths that have no ledger root, monkeypatch `HOME` to `tmp_path`.
- **[pattern]** To prove that new tests can fail, write a throwaway pytest plugin in `/tmp` that rebinds names in memory, chosen by a `--mutant` option. Run it with `uvx --python 3.13 --with pyyaml pytest -q -o pythonpath=/tmp/<dir> -p <plugin> -p no:cacheprovider --mutant <name> <test file>`. Production files stay untouched.
- **[gotcha]** At commit time, the commit gate scans every staged file and blocks on prose and comment findings such as `prose_colon`, `passive_voice`, `what_docstring`, and `long_comment`. Each block writes a report to `~/.adw/reports/`. Read the newest report with `/bin/ls -t ~/.adw/reports/*.json | head -1`. Plain `ls -t` is aliased in the agent shell and fails with `invalid value for '--time'`.
- **[pattern]** Before you commit, check staged docs and code yourself. Run `scan_all` from `hooks/lib/scanner.py` with `payload_hook_config` and `resolve_outcome` from `hooks/lib/config.py` in a script outside the repo, invoked with `python3 -I`. Fix every row that resolves to `block` and restage it, so the commit gate does not stop the commit.
- **[pattern]** To reproduce the CI pylint run locally, run `uvx --python 3.11 --with pytest --with pyyaml --from pylint pylint $(git ls-files '*.py')` from the repo root. Add `$(git ls-files --others --exclude-standard '*.py')` so new untracked modules are linted too. Without `--with pytest`, every test file reports E0401 `Unable to import 'pytest'` and the score drops to 9.85. Pylint exits nonzero on any single message. One leftover row drops the score to 9.95, and that fails CI.
- **[gotcha]** The full hooks suite (`cd hooks && uvx --python 3.13 --with pyyaml pytest -q . lib`) takes 12 to 13 minutes, measured at about 5760 tests in 700 to 790 s. That is more than the 600000 ms foreground Bash limit, and a foreground run gets moved to the background when it times out. Start it with `run_in_background: true` and read the task output file when it exits. For quick checks, run only the test files that cover your change.
- **[gotcha]** pytest-xdist is not installed, so `pytest -n auto` fails with `unrecognized arguments: -n`. You cannot parallelize the suite. Run it in the background instead.
- **[gotcha]** A headless `claude -p ... --allowedTools ...` delegation can only run the commands on its allowlist. In one run the test writer skipped its mutation check because copying `hooks/` to `/tmp` was not allowed. Allowlist every command the brief asks for, and check its report for skipped steps.
- **[gotcha]** In the agent shell (zsh), an unquoted glob flag such as `grep -rn X . --include=*.py` fails with `no matches found` before grep starts. Quote the pattern, as in `--include='*.py'`.
- **[pattern]** To check gate verdicts on a list of commands before you write tests, put a probe script in `/tmp` that inserts `hooks/` on `sys.path` and calls `pre_bash.run` or `record.run` with `ledger_root` and `state_root` under a temp folder. Point `reporting._reports_dir` at the same temp folder too, or every block writes a report into `~/.adw/reports/`. Run it with `uvx --python 3.13 --with pyyaml --with pytest python /tmp/<dir>/probe.py "<command>" ...`.
- **[pattern]** To prove that new tests fail on the old code, export HEAD with `git archive -o /tmp/head.tar HEAD hooks`, extract it into a separate `/tmp` folder, copy the new test files in, and run `uvx --python 3.13 --with pyyaml pytest -q -p no:cacheprovider -rA --rootdir /tmp/<tree>/hooks <tests>`. A test that passes at HEAD and still passes now only guards against loosening the gate.
- **[gotcha]** `long_comment` flags a comment line of roughly 15 words or more, and `what_docstring` flags a docstring that opens by naming what the code does, such as `Names the files...` or `Holds the open stage...`. Write a comment as one short `# Because X.` line. Open a docstring with the reason, as in `Because X, Y.`.
- **[pattern]** To reproduce the CI pylint run locally, run `uvx --python 3.11 --with pytest --with pyyaml --from pylint pylint $(git ls-files '*.py') $(git ls-files --others --exclude-standard '*.py')` from the repo root. The second list lints new untracked modules too. Without `--with pytest`, every test file reports E0401 `Unable to import 'pytest'` and the score drops to 9.85. Pylint exits nonzero on any single message. One leftover row drops the score to 9.95, and that fails CI.
- **[gotcha]** The full hooks suite (`cd hooks && uvx --python 3.13 --with pyyaml pytest -q . lib`) takes 8 to 13 minutes, measured at about 5860 tests in 500 to 790 s. That is close to or above the 600000 ms foreground Bash limit, and a foreground run that times out moves to the background. Start it with `run_in_background: true` and read the task output file when it exits. For quick checks, run only the test files that cover your change.
- **[pattern]** After a full run with many parametrized failures, run `pytest -q . lib --lf | grep -E '^FAILED' | cut -d'[' -f1 | sort | uniq -c` to group them by test function. Forty failures often turn out to be two tests.
- **[pattern]** To prove that new tests can fail, write a throwaway pytest plugin in `/tmp` that rebinds names in memory. Run it with `uvx --python 3.13 --with pyyaml pytest -q -o pythonpath="/tmp/<dir> ." -p <plugin> -p no:cacheprovider <test file>`. Keep `.` in `pythonpath` so the plugin can import `lib`. Select the mutant with a `--mutant` option or a mode file in `/tmp`. Production files stay untouched.
- **[pattern]** To prove that new tests fail on the old code, export HEAD with `git archive -o /tmp/head.tar HEAD hooks` and extract it into a separate `/tmp` folder with a small Python `tarfile.extractall(..., filter="data")` script. Run the same probe script or tests against both trees with `--rootdir /tmp/<tree>/hooks`. A test that passes at HEAD and still passes now only guards against loosening the gate.
- **[gotcha]** A headless `claude -p ... --allowedTools ...` delegation can only run the commands on its allowlist. In one run the test writer skipped its mutation check because copying `hooks/` to `/tmp` was not allowed. In another it could not delete its `/tmp` helper folder. Allowlist every command the brief asks for, and check its report for skipped steps.
- **[pattern]** To check gate verdicts before you write tests, put a probe script in `/tmp` that inserts `hooks/` on `sys.path` and calls `scan_all`, `payloads.split_edited_paths`, `pre_bash.run`, `record.run`, or `pre_commit.run` with `ledger_root` and `state_root` under a temp folder. Point `reporting._reports_dir` at the same temp folder too, or every block writes a report into `~/.adw/reports/`. Pass the hooks path as an argument, so one probe runs against both HEAD and the working tree. Run it with `uvx --python 3.13 --with pyyaml python /tmp/<dir>/probe.py <hooks path>`.
- **[gotcha]** Any change that moves files out of the written list into the imported list, as in `payloads.split_edited_paths`, can launder agent text past the gate. One such change let `curl -o app.py file:///.../scratch/mine.py` pass agent-written code as imported, and 42 R2-3 cases in `hooks/test_protected_write_routes.py` failed. Probe `file:` URLs, local clones, and archives the session wrote, and run `test_protected_write_routes.py` before you ship such a change.
- **[gotcha]** `json.dumps` escapes non-ASCII by default, so an em dash inside a JSON test fixture becomes `\u2014` and no dash rule can fire. Pass `ensure_ascii=False` when a fixture must keep a dash or other Unicode character, or the test passes for the wrong reason.
